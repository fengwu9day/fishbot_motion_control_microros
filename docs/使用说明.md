## 连接

```bash
docker run -it --rm -v /dev:/dev -v /dev/shm:/dev/shm --privileged --net=host \
  microros/micro-ros-agent:humble serial --dev /dev/ttyUSB1 -v4 -b 921600
```

这是在电脑上打开小车串口，收发 micro-ROS 数据。本机当前小车是 `/dev/ttyUSB1`，波特率 `921600`；雷达另接在 `/dev/ttyUSB0`。重插设备后先用 `ls -l /dev/serial/by-id /dev/ttyUSB*` 确认端口。OLED 必须是 `serial`。

屏幕若是 `udp_client` 或旧固件的 `wifi-client`，数据走 WiFi，这条串口命令连不上。双击板载按键可在串口和 WiFi 之间切换，板子会重启。单击只换页面。

## 检查

```bash
ros2 node list
ros2 topic info /cmd_vel -v
ros2 topic echo /odom --qos-reliability best_effort
ros2 topic echo /imu --qos-reliability best_effort
```

正常节点是 `/fishbot_motion_control`。`/cmd_vel` 订阅数应为 1，QoS 为 `BEST_EFFORT`。

## 速度指令

话题 `/cmd_vel`，类型 `geometry_msgs/msg/Twist`。只使用 `linear.x` 和 `angular.z`。必须带 `BEST_EFFORT`，否则终端仍会打印 `publishing`，板子收不到。

前进，0.05 m/s，每秒发 5 次：

```bash
ros2 topic pub -r 5 --qos-reliability best_effort /cmd_vel \
  geometry_msgs/msg/Twist "{linear: {x: 0.05}, angular: {z: 0.0}}"
```

发出的内容：

```text
linear:  x=0.05, y=0.0, z=0.0
angular: x=0.0,  y=0.0, z=0.0
```

停车，速度全为 0，每秒发 5 次。看到轮子停下后再按 `Ctrl+C`：

```bash
ros2 topic pub -r 5 --qos-reliability best_effort /cmd_vel \
  geometry_msgs/msg/Twist "{linear: {x: 0.0}, angular: {z: 0.0}}"
```

发出的内容：

```text
linear:  x=0.0, y=0.0, z=0.0
angular: x=0.0, y=0.0, z=0.0
```

不要用 `--once`。`Ctrl+C` 只停止发送，不会另发停车指令。当前固件会保持最后一次速度。

## Agent 调试日志

`-v6` 会把每一帧的原始字节打出来。这些不是速度命令的回显。

| 日志 | 方向 | 含义 |
| --- | --- | --- |
| `DataWriter write`，`<<DDS>>` | 板子 → ROS 2 | Agent 正在发布一帧话题 |
| `recv_message`，`SER` | 板子 → Agent | 串口刚收到的原始字节，比话题内容多出 micro-ROS 传输头 |
| 发往串口、再由 DDS 读出的日志 | ROS 2 → 板子 | 才是 `/cmd_vel` 那一类指令 |

一帧 `/imu` 常见长度是 312 字节，类型 `sensor_msgs/msg/Imu`。串口那一行往往是 324 字节左右，多出来的是传输头。日志里的 `69 6D 75 00` 就是坐标系名字 `imu`。

固件填入的字段：

- 时间戳
- 坐标系 `imu`
- 姿态四元数 `orientation`
- 角速度 `angular_velocity`
- 线加速度 `linear_acceleration`

三段协方差保持为 0，固件没有填写。驱动直接使用 MPU6050 库的返回值，没有换成 ROS 标准单位：角速度多半是度/秒，加速度多半是 g，而不是消息定义里的弧度/秒和 m/s²。

不必从十六进制里读。用上面的 `ros2 topic echo` 即可。
